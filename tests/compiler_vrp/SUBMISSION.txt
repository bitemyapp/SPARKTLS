Subject: [RFC PATCH] tree-optimization: Preserve full extent of array slices

An Ada array slice can access more than one element beyond its starting
index. get_ref_base_and_extent currently applies its single-element
range-based upper-extent formula to ARRAY_RANGE_REF as well as ARRAY_REF.
With a four-byte slice and starting indices 0..28, IPA modref consequently
records only 232 bits of possible writes instead of the required 256 bits.
The caller then incorrectly reuses pre-call values of the final three bytes.

Restrict this upper-extent refinement to ARRAY_REF. For ARRAY_RANGE_REF,
retain the existing conservative extent and lower-offset refinement.
This leaves VRP and the ordinary scalar-array optimization enabled.

The attached dependency-free Ada test fails on unpatched GCC 16.1.0 at
-O2 -gnatp and -O3 -gnatp, and passes with the patch. It was reduced from
SPARKNaCl's SHA-256 output serialization. No cryptographic library is needed
to reproduce it.

its golden file. Selected existing GCC regression checks also pass.
See BUG_REPORT.md for details and the exact compiler configuration.

This is an RFC with targeted validation, not a merge-qualified submission.
The mainline patch is apply-checked against the exact base above; it has
not had a full mainline build. A complete bootstrap and regression run of
the required languages and runtimes is still needed before requesting merge.
